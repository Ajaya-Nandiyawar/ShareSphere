## Context

SRS Sec 3.6 specifies two options for local PHP development on Windows (NFR-PRT-01 [M]):
- **XAMPP**: A bundled environment providing Apache, PHP, and a database (MariaDB by default, but we use PostgreSQL).
- **PHP Built-in Server**: The `php -S localhost:8000 -t public` command.

The frontend uses Vite dev server on port 5173 with a proxy for `/api` pointing to the PHP dev server.

---

## Options

### Option A — XAMPP (Apache + PHP)

| Criterion | Assessment |
|-----------|-----------|
| **Effort** | Medium. Requires developers to install XAMPP, configure a VirtualHost for the `sharesphere/backend/public` directory, and ensure the `.htaccess` routing works. |
| **Risk** | Low. Provides a robust Apache environment that closely mirrors a production Apache setup (ADR-003). |
| **NFR-PRT-01 fit** | Full. XAMPP is explicitly named in the requirement. |
| **Extensions** | XAMPP for Windows usually has the required extensions (`pdo_pgsql`, `sodium`, etc.) but they may need to be uncommented in `php.ini`. |
| **SRS constraints violated** | None identified. |

### Option B — PHP Built-in Server (`php -S`)

| Criterion | Assessment |
|-----------|-----------|
| **Effort** | Low. Zero configuration. A simple `npm run serve:api` script can execute `php -S localhost:8000 -t backend/public`. |
| **Risk** | Low for development. Not suitable for production (single-threaded), but perfect for the Vite proxy. It does not process `.htaccess` files, so a router script (like `public/index.php`) must handle all traffic. |
| **NFR-PRT-01 fit** | Full. Supported on all OS platforms where PHP is installed natively (Windows, Linux). |
| **Extensions** | Relies on the globally installed PHP CLI `php.ini`. |
| **SRS constraints violated** | None identified. |
