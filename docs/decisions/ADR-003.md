## Context

SRS Sec 3.1 and 3.6 list **"Apache 2.4 / Nginx + PHP-FPM"** for the production web server.
The production web server must:
- Statically host the compiled React files from `/var/www/sharesphere/public`.
- Forward `/api/*` requests to the PHP application (`public/index.php`).
- Serve TLS (HTTPS) via Let's Encrypt (SRS Sec 3.6).
- Set security headers (CSP, HSTS, X-Content-Type-Options) if not fully handled in PHP (NFR-SEC-01).

---

## Options

### Option A — Apache 2.4 (with mod_rewrite and mod_ssl)

| Criterion | Assessment |
|-----------|-----------|
| **Effort** | Medium. Requires setting up VirtualHosts and enabling modules (`mod_rewrite`, `mod_ssl`). The `.htaccess` file can hold the rewrite rules, making it easy to deploy alongside the PHP code. |
| **Risk** | Low. Mature, extremely widely documented. Often runs PHP via `mod_php` which is simpler, but PHP-FPM via `mod_proxy_fcgi` is modern practice. |
| **NFR-PRT-01 fit** | Full. Easily runs on Linux and Docker. Aligns well with Windows XAMPP which uses Apache natively. |
| **Routing / FR-METH-02** | Easily achieved using `FallbackResource` or `RewriteRule` in `.htaccess`. |
| **SRS constraints violated** | None identified. |

### Option B — Nginx + PHP-FPM

| Criterion | Assessment |
|-----------|-----------|
| **Effort** | Medium. Requires setting up Nginx server blocks and configuring `fastcgi_pass` to the PHP-FPM socket/port. Configuration must be applied to the server directly, as Nginx has no `.htaccess` equivalent. |
| **Risk** | Low. The industry standard for high-performance PHP hosting. Excellent concurrency. |
| **NFR-PRT-01 fit** | Full. Easily runs on Linux and Docker. Diverges slightly from Windows XAMPP dev environment, but this is typical. |
| **Routing / FR-METH-02** | Easily achieved using `try_files $uri $uri/ /index.php?$query_string;`. |
| **SRS constraints violated** | None identified. |
