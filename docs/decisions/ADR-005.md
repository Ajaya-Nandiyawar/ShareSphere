## Context

SRS Sec 3.4 outlines session storage alternatives:
- Default file-based PHP sessions in development.
- An optional PDO session handler (table `php_sessions`).
- Redis for horizontally-scaled deployments.

The application requires strict session controls:
- `session_regenerate_id(true)` on login (FR-SESS-01).
- Idle and absolute timeouts (FR-SESS-02).
- Concurrent request safety.

---

## Options

### Option A — Default File-based Sessions

| Criterion | Assessment |
|-----------|-----------|
| **Effort** | Zero. PHP default. |
| **Risk** | Low for single-node deployments. If the app is load-balanced across multiple containers (without sticky sessions), file-based sessions will fail because the files are local to the container. |
| **SRS constraints violated** | None for single-node. Fails scaling requirements if Docker Swarm/K8s is used. |

### Option B — PDO Session Handler (PostgreSQL)

| Criterion | Assessment |
|-----------|-----------|
| **Effort** | Medium. Requires implementing PHP's `SessionHandlerInterface` using PDO, creating a `php_sessions` table, and handling garbage collection. |
| **Risk** | Low-Medium. Adds database load for every request (read/write session data). However, it cleanly supports multi-node deployment since PostgreSQL is centralized. |
| **SRS constraints violated** | None identified. |

### Option C — Redis Session Handler

| Criterion | Assessment |
|-----------|-----------|
| **Effort** | Medium. Requires the `php-redis` extension and a running Redis server. Configuration is a simple `ini_set('session.save_handler', 'redis')`. |
| **Risk** | Medium. Introduces a new infrastructure dependency (Redis) not currently mandated by the SRS. |
| **SRS constraints violated** | **Potential violation:** SRS Sec 2.4 and 3.1-3.7 do not list Redis as a required runtime dependency. Adding it increases ops complexity beyond the stated stack. |

---

## SRS Constraints That Would Be Violated by Each Option

| Option | Potential Violation | Condition |
|--------|--------------------|-----------:|
| Option A | None | Assumes single-node or sticky-session deployment. |
| Option B | None | — |
| Option C | SRS Sec 2.4, 3.1 | Redis is not in the approved technology stack for the runtime/database layers. |
