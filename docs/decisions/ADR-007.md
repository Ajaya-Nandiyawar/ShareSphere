## Context

SRS Sec 3.6 lists Docker and Docker Compose as an *optional* deployment method.
The prompt specifies the application must run on Windows (XAMPP), Linux, and Docker with environment variables only (NFR-PRT-01 [M]).

The question is whether the team will actively maintain and mandate Docker configurations (e.g., `docker-compose.yml`, `Dockerfile`s) in the repository as a primary artifact, or rely purely on bare-metal/XAMPP instructions.

---

## Options

### Option A — Provide and Maintain Docker configurations

| Criterion | Assessment |
|-----------|-----------|
| **Effort** | Medium. Requires creating and testing a `docker-compose.yml` defining `web` (nginx), `app` (php-fpm), `db` (postgis), and `mailhog` services. |
| **Risk** | Low. Docker actually reduces "works on my machine" risks by standardising the environment. |
| **NFR-PRT-01 fit** | Full. Directly satisfies the "runs on Docker" requirement. |
| **SRS constraints violated** | None identified. |

### Option B — No Docker (Rely on XAMPP / bare-metal only)

| Criterion | Assessment |
|-----------|-----------|
| **Effort** | Zero. |
| **Risk** | Medium. Differences between developer machines (Windows vs Mac vs Linux, different PHP minor versions, missing extensions) can cause integration bugs. |
| **NFR-PRT-01 fit** | Partial. Fails to explicitly prove the "runs on Docker" requirement if no Docker artifact is tested. |
| **SRS constraints violated** | **NFR-PRT-01** ("Runs on ... Docker"). If we don't provide a way to run it on Docker, we cannot prove this requirement is met. |

---

## SRS Constraints That Would Be Violated by Each Option

| Option | Potential Violation | Condition |
|--------|--------------------|-----------:|
| Option A | None | — |
| Option B | **NFR-PRT-01** | The SRS explicitly requires the system to run on Docker. |
